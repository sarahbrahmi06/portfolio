★ Research Note

Humans vs. Machines in Malware Classification

Paper review: Aonzo, Han, Mantovani & Balzarotti (USENIX Security 2023)

AI for Cybersecurity ML Detection Human-AI Teaming

Paper Information

Title Humans vs. Machines in Malware Classification
Authors Aonzo, S., Han, Y., Mantovani, A., & Balzarotti, D.
Venue 32nd USENIX Security Symposium (USENIX Security '23)
Institutions EURECOM / INRIA
Topics AI for Cybersecurity · ML-based Malware Detection · Human-AI Teaming · Explainable AI
Read Original Paper

TL;DR: Aonzo et al. placed 110 human analysts and two state-of-the-art ML models side-by-side in a controlled malware classification game. The central finding: humans and machines extract fundamentally different information from the same data, and neither is universally superior. Human analysts converged on dynamic behavioral features, while ML models relied heavily on static file properties. When the models were restricted to human-preferred features, their accuracy collapsed while human experts stayed accurate.

Why I Read This Paper

As a cybersecurity student specializing in AI for security, I wanted to understand a question that sits at the heart of everything I'm building: when a machine learning model flags a file as malicious, is it looking at the same things a human analyst would?

This paper presents an empirical study examining that question by placing 110 human analysts (72 novices, 38 experts) and two state-of-the-art ML models side-by-side in a controlled malware classification task. The findings challenged several of my assumptions about how I should design and evaluate AI-based detection systems.

The Setup: A Game That Reveals Decision-Making

The researchers built an online game called "Detect Me If You Can!" (DMIYC) where players classify 20 real-world PE files (11 malware, 9 goodware) using sandbox reports. The design is notable: players start with a blank report and must "buy" each feature (static or dynamic) at a cost of one point per feature. This incentivizes players to reveal which features they actually value rather than selecting everything indiscriminately.

DMIYC feature catalog ~
Static Features:
├── VT Labels · VT Submission History · Signature
├── Header Metadata · Sections · Imports
└── Resources · Strings

Dynamic Features:
├── Network · Processes · Services · Registry
└── Mutexes · File System · Runtime DLLs

The ML players (Random Forest and CNN) were trained on 21,944 VirusTotal reports balanced between malware and goodware and then evaluated on the same 20 game samples.

Key Findings

1. Humans Converge on Similar Features Regardless of Expertise

Both experts and novices converged on the same top five features, though in slightly different order:

Rank Experts Novices
1Network (dynamic)VT Labels
2VT LabelsNetwork (dynamic)
3Processes (dynamic)Signature
4FileSystem (dynamic)Processes (dynamic)
5SignatureFileSystem (dynamic)

Experts were faster (29 min vs. 44 min) and more accurate (16.1 vs. 13.7 correct on average), but they used a similar number of features. The primary difference appears to be interpretation speed rather than feature selection strategy. This suggests that feature selection is relatively consistent across the two groups in this study a useful insight for designing training tools and explainable AI interfaces.

2. ML Models and Humans Relied on Substantially Different Features

A key finding: the ML models prioritized different features from human analysts:

Rank Random Forest CNN Human Experts
1 Resources (static) Resources (static) Network (dynamic)
2 Services (dynamic) Sections (static) Processes (dynamic)
3 Header Metadata (static) Network (dynamic) FileSystem (dynamic)
4 Network (dynamic) Runtime DLLs (dynamic) Signature (static)
5 Signature (static) Header Metadata (static) Registry (dynamic)

Resources the feature ML models ranked first was ranked last by human experts and was almost never used. Humans preferred dynamic behavioral features; machines preferred static file properties.

The authors offer several explanations for this divergence:

Dynamic features are frequently missing. Over the training dataset of 21,944 samples, 83% had at least one dynamic feature containing NULL values. A program does not need to exercise every operating system capability. ML models treat missing values as noise, which weakens the statistical association between dynamic features and labels. Humans, by contrast, can reason with partial information.

Static features are rarely missing. PE headers, sections, and resources exist in every executable. ML models gravitate toward what is consistently available.

Humans can incorporate external context. When a human encounters a suspicious domain such as phone2347.ddsn[.]net, they can search for it, recognize it as a dynamic DNS resolver, and apply external knowledge. ML models are constrained to the feature space defined at training time.

3. The "Game Replay" Experiment

This experiment is particularly relevant for anyone building human-AI collaborative systems.

The researchers retrained the ML models using only the top 5 or top 7 features that humans actually used, then replayed the game using the exact same features each human expert had selected for each sample.

Method Top 5 Features Top 7 Features
Random Forest 4/8 correct 5/13 correct
CNN 3/8 correct 5/13 correct
Human Experts 8/8 correct 13/13 correct

In this specific replay setting, the ML models' classification accuracy on the game samples was lower than what would be expected from chance, while human experts classified all samples correctly under the same feature constraints.

The authors attribute this to several factors:

  • Human experts rarely used more than three features to reach a decision, relying on heuristics rather than exhaustive data.
  • ML models generally require complete feature vectors; missing values (which humans handle naturally) degrade their accuracy.
  • The features humans find most informative (dynamic behavior) are the ones ML models find least stable due to sparsity and missing data.

What This Means for AI for Cybersecurity

For Detection System Design

This paper suggests that high cross-validation performance does not guarantee that a model has learned what human analysts learn. In the 5-fold cross-validation reported in the paper, the RF and CNN models achieved AUC-ROC scores of 0.9962 and 0.9950 respectively. However, when evaluated on the game samples some of which were specifically crafted to reflect complex real-world situations such as false positives and false negatives both models misclassified certain samples that human experts handled correctly.

Practical takeaway: When evaluating a detector, test it on samples where human analysts agree on the verdict, and examine whether the model's feature attributions (via SHAP or similar techniques) align with human reasoning. If they do not, the model may be exploiting statistical correlations that do not correspond to the features human analysts considered informative.

For Human-AI Teaming

The paper illustrates that humans and machines have complementary strengths:

Humans Machines
Flexible reasoning Process all features simultaneously
External knowledge integration Capture subtle statistical patterns
Handle missing data Scale across large datasets
Case-by-case strategy adjustment Consistent, non-fatiguing evaluation

This suggests that an effective system may not be "AI replaces analyst" but rather AI augments analyst and vice versa. For example:

  • ML can highlight which static features (such as Resources or Header Metadata) are anomalous, directing human attention to parts of the file they might otherwise skip.
  • Humans can provide feedback on dynamic behavior that ML models struggle to encode, potentially creating a continuous learning loop.

For Explainable AI (XAI)

The paper used SHAP (Shapley Additive Explanations) to rank feature importance for the ML models. This is precisely the kind of technique relevant to making black-box models interpretable so analysts can understand and debug them. The finding that ML relies on Resources while humans largely ignore it is visible because of SHAP analysis. Without explainability, this divergence might not have been identified.

Limitations and Open Questions

The authors are transparent about constraints:

  • Game mechanics: The cost of buying features may have pressured players to under-investigate. Real analysts might use more features.
  • Sample size: 20 samples is small, though carefully curated. The goodware includes popular applications (Chrome, TeamViewer) that might have distinctive static signatures.
  • Feature encoding: The ML models used Word2Vec embeddings for categorical features a standard but imperfect approach for sparse dynamic data.
  • No eye-tracking: The study could not capture which part of a feature (e.g., which specific string or registry key) triggered a decision.

These limitations suggest future work: larger-scale studies, improved dynamic feature encoding, and real-time human-AI collaboration experiments.

How This Shapes My Research Direction

This paper clarified several directions I want to pursue:

1. Build explainable malware classifiers. I want to work on models where I can trace why a decision was made not just report accuracy metrics. SHAP, LIME, and attention mechanisms are tools I am actively learning.

2. Design human-in-the-loop detection systems. The paper illustrates that human and machine intelligence are not interchangeable. I want to build interfaces that surface ML insights to analysts and allow analysts to correct ML mistakes in real time.

3. Study feature robustness. The paper shows dynamic features are sparse and missing-prone. I want to explore techniques for handling incomplete behavioral data perhaps using generative models (as the authors suggest) or causal inference to reconstruct missing features.

4. Evaluate beyond accuracy. A model with high AUC that fails on human-trivial samples may not be deployable. I want to develop evaluation protocols that measure alignment with human reasoning, not just statistical performance.

Conclusion

This paper is valuable reading for anyone at the intersection of AI and security. Its central message is that machines and humans extract different information from the same data, and neither is universally superior. The ML models achieved high cross-validation scores but, in the specific replay setting, failed when restricted to human-preferred features. Human experts achieved approximately 80% accuracy on average but could not classify every sample correctly either.

The path forward is likely not replacement but collaboration building systems where ML handles scale and statistical subtlety, while humans provide context, flexibility, and causal reasoning. For a student preparing for an internship in AI for cybersecurity, this paper provides both a technical roadmap (XAI, human-in-the-loop design, robust feature encoding) and a grounding principle: the goal is not to build AI that thinks like a human, but to build AI that works with humans.

Citation

Aonzo, S., Han, Y., Mantovani, A., & Balzarotti, D. (2023). Humans vs. Machines in Malware Classification. 32nd USENIX Security Symposium (USENIX Security '23).
